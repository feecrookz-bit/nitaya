Stock tracker link

Steps for Coleisha and Simar. The aim is a fixed doorway between the website and the stock tracker, so Simar can keep changing the script without breaking the site. Nothing gets built at the meeting. The output is one agreed field list.

Simar before the meeting

  1. Add a product code column to the Database Products tab and fill it for every active row. Same code as the WooCommerce SKU where one exists; make one up in the same style where it doesn't.
  2. Add rows for Sinai Pearl and for each of the six cladding colours (currently one row).
  3. Decide where "available" comes from: a column someone keeps, or a formula from your movements. Either is fine, but pick one.
  4. Make a test copy of the sheet and script with a handful of products and made-up stock.

Coleisha before the meeting

  1. Open the site preview and note how each product is sold: per pack, per slab, per box, per bucket. Mixed patio packs can be split into their four slab sizes; this is the case the sheet must handle.
  2. Print the two field tables on the next page.
  3. Bring the list of five listings that disagree with the sheet (item 10 of the handover), so Simar can say which is right.

Together about 30 minutes, the sheet open

  1. Go down the Read stock table. For each field, write which column it comes from and what a blank means.
  2. Go down the Record order table. Agree how a split pallet is recorded, and whether stock drops when an order is recorded or when it leaves the yard.
  3. Agree the four things Simar keeps stable from now on: the web app address, the shared secret, the two entry point names, the field names. Everything else in the script is his to change.
  4. Agree how he tells us about changes. A Changelog tab in the sheet is enough.

After

  • Coleisha writes the agreed list up and sends it to Fee. Fee connects the site to the test copy first, then the live one.
  • Simar deploys the two entry points as a Google web app on one permanent address (deploy once, then publish new versions to the same deployment) and gives the address and the secret to Fee by phone, not email.

Questions to settle in the room. Is stock counted in slabs or in pallets? When a customer takes nine loose slabs from a pallet, how is the broken pallet recorded? Does stock drop when an order is recorded or when the goods leave the yard?

What stays fixed, what can change

Fixed: the web app address, the shared secret, the names of the two entry points, and the field names above.
Free to change: everything else in the script and the sheet: columns, tabs, formulas, roles, layout. If a fixed thing must change, add the new version alongside the old and say so in the Changelog before the old one goes.
